How to read the lab

Impact recall asks whether the selector's predicted scope contains the nodes that were truly affected. Coverage asks whether the chosen tests traverse those affected nodes. Probability of detection uses each test's failure-mode-specific oracle strength. These are deliberately different evidence planes.

Falsification move. Use “Inject diagnostic fault”. The lab searches for a critical failure mode on a node exercised by the selected suite but weakly observed by its oracles. The parity fixture contains an explicit case with covered = true and POD = 0.

Migration and parity

The original executable prototype was created in the Diderot Machine Learning Specialization repository before the canonical Diderot home was corrected to this interactive encyclopedia. The “Python migration oracle” freezes one reference run from that implementation. CI checks that the browser core reproduces R0–R5 selected test sets, predicted impacts, evaluation metrics, and the coverage-versus-detection invariant on that fixture.

Interactive browser worlds use a small deterministic JavaScript RNG, so arbitrary browser seeds are not claimed to reproduce NumPy PCG64 sample-for-sample. The parity fixture is the cross-implementation contract.

Evidence boundary

The topology, change frequencies, edge probabilities, test costs and POD values are synthetic experimental parameters. They are not measurements of a production identity system and are not evidence that selective regression or AI-assisted selection is superior. Negative, tied, or worse R5 results are valid outcomes.
