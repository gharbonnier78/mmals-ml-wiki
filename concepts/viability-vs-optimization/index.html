Viability vs optimization

Keeping an adaptive system inside an admissible region can be a different design problem from maximizing one scalar score.

open hypothesisadded 2026-09-03stable /go/ link

In plain language

“Best” is not always the same as “still able to function”. A system can trade some immediate performance for safety margin, diversity, recoverability or the ability to adapt later.

Engineering view

An optimization-only controller asks which admissible choice scores highest now. A viability-aware controller first rejects choices that would leave required safety, competence, resource or recoverability bounds, then optimizes within the remaining region.

Research view

For MMALS this is a candidate alternative to treating continual learning as one fixed scalar objective. The hypothesis is that explicit viability constraints may preserve useful optionality under distribution shift. This requires controlled comparison against ordinary regularized optimization and constraint-based baselines.

Formal anchor

first remain viable; then optimize among viable alternatives
open hypothesis
Current evidence

Evolutionary biology motivates the warning that living systems should not be read as globally optimized designs. No MMALS experiment yet establishes a viability-aware objective as superior.

Boundary

This page does not claim that biological evolution solves an engineering viability problem or that optimization should be abandoned.

Why it matters for MMALS

Reuse → adapt → fork can be interpreted as preserving validated competence and future adaptive capacity before spending complexity on a new regime. That interpretation is testable only if “viable” is translated into explicit engineering constraints.

Misconception

Wrong: viability means accepting mediocre performance. Correction: viability separates mandatory survival/competence constraints from the score optimized inside those constraints.

Understanding gate

Give one example where the numerically best immediate action would violate a long-term competence, resource or safety constraint.
