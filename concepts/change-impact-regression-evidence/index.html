Change impact & regression evidence

Regression scope should be justified from plausible propagation and failure mechanisms before the existing test suite is used as an evidence inventory.

Methodological research candidateadded 2026-08-18stable /go/ link

In plain language

Retesting asks whether the thing you changed still works. Regression asks what else the change may have disturbed. The second question must begin by understanding where effects could travel, not by opening the old test catalogue and choosing convenient tests.

Engineering view

Model the change, plausible propagation paths, failure mechanisms, critical consequences and evidence needs. Only then map those needs onto existing tests or create missing observations. Record both selected and deliberately omitted evidence, plus residual uncertainty.

change → propagation → failure mechanism → consequence → evidence need → regression selection

Research view

The method creates separable assurance planes: impact adequacy, exercise/coverage, detection power, evidence actionability and accountable decision. Candidate strategies R0–R5 can be compared on critical-impact recall, critical miss rate, execution cost and fault-detection endpoints without assuming that selective regression or AI is superior.

Formal anchor

Gtrue ≠ Gobserved

The experimental simulator separates the system's hidden propagation reality from the incomplete engineering graph available to selectors. This prevents a trivial experiment in which the selector is handed the truth it is supposed to discover.

Synthetic experimental support only
Current evidence

An executable Diderot lab implements a synthetic distributed system, R0–R5 selection strategies, explicit failure-mode injection, probability-of-detection reasoning and a Python-to-browser migration parity fixture.

Boundary

The topology, propagation probabilities, test costs and POD values are synthetic. They do not establish production frequencies, release thresholds or AI superiority.

Core non-implications

Scope: high coverage cannot repair an important propagation path that was never selected.
Detection: traversing a component does not imply that the test oracle detects a meaningful failure there.
Decision: detecting a failure does not by itself prove that the resulting evidence is sufficient for release or residual-risk acceptance.
