Belief ≠ model ≠ memory

Three different objects answer three different questions: what is probably true now, how the system is expected to evolve, and what prior evidence or competence should remain recoverable.

project synthesisadded 2026-09-01

Intuition

A belief should change when evidence changes. A transition model encodes how states and observations are expected to evolve. Memory preserves experience, validated competence, provenance or reusable structure. Collapsing all three into one vector hides different update and governance requirements.

b_t\;\;\neq\;\;\theta_t\;\;\neq\;\;M_t

Concrete example

A system may revise its belief from “regime A likely” to “regime B likely” without deleting the learned capability that previously solved regime A. The capability can remain protected in memory even though the current belief must remain revisable.

Mathematical descent

bt is an information state conditioned on current history. θt denotes parameters or structure of the learned dynamics/inference model. Mt denotes stored evidence, exemplars, snapshots or functional anchors used to recover or protect previous competence. Their update laws need not be the same.

In plain language

“What I currently believe”, “how I think the world works”, and “what I refuse to forget without evidence” are related but not identical.

Misconception

Wrong: protecting an old belief from change is a valid way to prevent catastrophic forgetting. Correction: a belief should be revised by evidence; protection belongs to validated competence, constraints, evidence provenance or model components, depending on the system.

Understanding gate

Describe one update that should change the belief while leaving an old competence intact, and one model revision that should trigger a new validation obligation.

Boundary

This is a project synthesis for MMALS/world-model reasoning, not a claim that every architecture must physically separate three tensors or modules.
