Terminology & semantics

Canonical research object

In a governed experiment, canonical means the currently authorized reference used to support a scientific decision. It does not mean “absolute truth”, “best available result”, or “the file with the familiar name”.

Evidence governancereviewed 2026-08-25

In plain language

If several copies, reruns, mirrors, or diagnostic alternatives exist, the canonical object is the one the study currently recognizes as the reference for the decision. Another result may be newer or more plausible, but it does not replace the canonical one until the replacement is justified and recorded.

Engineering view

A canonical object should be reconstructible from stable identifiers: repository and commit, protocol version, model and dataset identities, cryptographic digests, run identifier, result artifact, and decision record. File names alone are insufficient identities.

Research view

Canonicality is a governance relation between an evidence object and a decision state. It is not an epistemic claim that the object is infallible. A later diagnostic may invalidate a canonical object; the proper response is an append-only correction or supersession event, not silent retrospective replacement.

Semantic distinctions

TermMeaning in this wiki
CanonicalThe currently authorized reference for a bounded decision.
Official / first-partyA source maintained by the original authors, institution, standards body, or owner of the referenced object.
Validated mirrorA transport copy used in an experiment whose exact bytes or functional identity were checked. It does not become first-party merely because it was validated.
DiagnosticEvidence produced to explain an anomaly or test a competing explanation. Diagnostic evidence has no gate authority unless a protocol explicitly grants it.
Historical / supersededAn object that once had authority but was later replaced through an explicit correction, replay, or version transition.

Contextual example — Study 1A CFP-FP

In the Siamese Embedding Compression Lab, the canonical CFP-FP result is currently the result produced by the authorized Study 1A A1/A2 run using the frozen checkpoint, protocol, threshold and the exact CFP-FP artifact pinned by SHA-256. That result is currently a FAIL for CFP-FP.

Two alternative CFP-FP mirrors are being evaluated diagnostically to test whether the transport artifact differs from the one expected by the AdaFace reference evaluation. Those diagnostic runs may reveal a provenance defect, but they do not automatically replace the canonical result. If they demonstrate a real defect, a separately reviewed correction/replay may designate a new canonical result while preserving the previous one as historical evidence.

Why this matters

Without this distinction, a research workflow can drift into outcome shopping: the most convenient or favorable rerun becomes “the result”. Canonicality forces the decision surface to remain stable until there is an explicit, reviewable reason to change it.
