Reinforcement learning, MDPs, and decision risk

Reinforcement learning chooses actions through time; an MDP formalizes the environment in which those actions change state, produce rewards, and expose the agent to uncertain future consequences.

Foundational synthesisreviewed 2026-08-16stable /go/ link

In plain language

An agent repeatedly observes where it is, chooses what to do, and receives feedback. A good action is not merely one that pays immediately: it should lead toward a good total future. When actions can slip or fail, the agent compares the average return over all possible futures.

Engineering view

An MDP separates state, action, transition probability, reward, and discount. A policy maps state to action. The optimal state-action value Q obeys a Bellman recursion. In a stochastic environment, that recursion is an expectation over possible next states and rewards.

Research view

Expected-return optimization is risk-neutral with respect to the modeled return distribution. Safety-critical decision support may additionally require hard invariants, chance constraints, lower-tail quantiles, CVaR, uncertainty bounds, and explicit human judgment. Extending this foundation to MMALS belief-state control remains a research hypothesis, not an established result.

1. From reinforcement learning to an MDP—and back

Reinforcement learning (RL) is the learning problem: an agent must discover how to act through interaction so that its long-term outcome is good. A Markov decision process (MDP) is the mathematical model used to state that problem precisely.

MDP = (S, A, P, R, \gamma)
ObjectMeaningMars-rover example
SSet of states describing the decision-relevant situationSix rover positions
AActions available to the agentMove left or move right
P(s'|s,a)Probability of reaching next state s' after action a in state sA commanded move succeeds with probability 0.9 and slips with probability 0.1
RImmediate feedback associated with a transition or state100 at the left terminal, 40 at the right terminal, 0 elsewhere
γDiscount factor controlling the weight of later rewardsFor example, γ = 0.5

The direction of explanation is therefore circular only in appearance:

  1. RL gives the practical objective: learn how to act.
  2. The MDP supplies the formal world: states, actions, transitions, rewards, and time preference.
  3. RL algorithms use experience or a known model to solve that MDP approximately or exactly.
  4. The result is a policy that maps situations back to actions.
Markov property. Once the current state is known, earlier history adds no information needed to predict the next state under the selected action: P(St+1|St,At,history)=P(St+1|St,At). This is a modeling claim about the adequacy of the state representation, not a claim that the physical world has no history.

2. The agent–environment loop

At time t, the agent observes state St, selects action At, then the environment produces an immediate reward and a next state. The cycle repeats until a terminal state ends the episode.

S_t \xrightarrow{\;A_t\;} (R_{t+1}, S_{t+1})

An action is a command or decision, not necessarily its realized physical outcome. In the stochastic rover, “left” is the intended direction; slipping can still produce a move to the right.

3. Reward is local; return is temporal

A reward says whether one immediate outcome is desirable. It does not by itself compare trajectories whose useful consequences occur at different times. The return aggregates the reward sequence:

G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots

The discount factor γ, usually between 0 and 1, makes distant rewards count less. A small γ produces an impatient agent; a γ close to 1 makes the agent more willing to wait. Discounting can represent time preference, uncertainty about distant outcomes, finite effective horizon, or a mathematical device ensuring convergence. These interpretations should not be silently conflated.

4. A policy tells the agent what to do

A deterministic policy maps each state to an action:

\pi(s)=a

A stochastic policy instead gives action probabilities, π(a|s). The course rover policy may, for example, command left in states 2, 3, and 4, and right in state 5. A policy describes behavior; it is not yet proof that the behavior is optimal.

5. State-action value Q(s,a)

The optimal state-action value answers a precise counterfactual question:

If the agent is in state s, takes action a now, and behaves optimally afterward, what total discounted return should it expect?
Q^*(s,a)=\text{expected return after taking }a\text{ in }s\text{, then following }\pi^*

The first action is fixed by the argument a. Only subsequent actions follow the optimal policy. This resolves a common confusion: Q is defined relative to future behavior, but it is used to recover that behavior:

\pi^*(s)=\arg\max_a Q^*(s,a)

The associated optimal state value keeps only the value of the best available action:

V^*(s)=\max_a Q^*(s,a)

Thus V*(s) asks how valuable the state is under optimal behavior, while Q*(s,a) asks how valuable one particular first action is. The star emphasizes optimality. Some introductions, including parts of the course sequence, write Q when the optimal meaning is clear from context.

6. Bellman recursion in a deterministic environment

The Bellman equation decomposes long-term value into “reward now” plus “discounted value afterward.” If action a deterministically reaches s':

Q^*(s,a)=R(s,a,s')+\gamma\max_{a'}Q^*(s',a')

Here a' means an action available in the next state. The maximum selects the best continuation, not the best immediate reward. At a terminal state there is no future continuation, so the recursive future term disappears under the course convention. The lesson often writes the immediate term as R(s); the more general R(s,a,s') notation used here allows reward to depend on the action and realized transition.

7. Stochastic transitions: one action, several possible futures

In a stochastic environment, the same state and action do not determine one unique next state. From rover state 4:

  • command left: reach state 3 with probability 0.9, but state 5 with probability 0.1;
  • command right: reach state 5 with probability 0.9, but state 3 with probability 0.1.

Repeated execution of the same policy can therefore generate different trajectories, different reward sequences, and different realized returns. The return G becomes a random variable.

8. The “famous E”: expected return

The symbol 𝔼 denotes mathematical expectation. It is a probability-weighted average, not a squared mean and not a mean-squared error.

\mathbb E[G]=\sum_i P(G=g_i)\,g_i

Empirically, one can execute a policy many times, calculate one discounted return per episode, and average those returns:

\mathbb E[G] \approx \frac{1}{N}\sum_{i=1}^{N}G^{(i)}

An expected return need not be a value ever observed in one episode. If the return is 100 with probability 0.9 and 40 with probability 0.1, then 𝔼[G]=94, even though an episode produces 100 or 40, not 94.

9. Stochastic Bellman equation

Because the next state and possibly the reward are random, Bellman now averages over their conditional distribution:

Q^*(s,a)=\mathbb E\!\left[R_{t+1}+\gamma\max_{a'}Q^*(S_{t+1},a')\mid S_t=s,A_t=a\right]

For discrete next states:

Q^*(s,a)=\sum_{s'}P(s'|s,a)\left[R(s,a,s')+\gamma\max_{a'}Q^*(s',a')\right]

Using the course notebook values V*(3)=21.25, V*(5)=18.52, and γ=0.5, with zero immediate intermediate reward:

Q^*(4,left)=0.9(0.5\times21.25)+0.1(0.5\times18.52)\approx10.49
Q^*(4,right)=0.1(0.5\times21.25)+0.9(0.5\times18.52)\approx9.40

The optimal action is left because 10.49 exceeds 9.40. Raising the misstep probability generally lowers the attainable values because the agent has less control, although the exact effect and whether the optimal policy changes depend on the full reward and transition structure.

10. What expected-return optimization leaves out

Standard RL commonly selects

\pi^*=\arg\max_\pi \mathbb E[G_\pi]

This is risk-neutral with respect to the modeled return distribution: policies with the same expectation are equivalent to this objective even when one is stable and the other has a catastrophic tail.

PolicyDistributionExpected returnOperational meaning
A50 with probability 150Stable outcome
B100 with probability 0.5; 0 with probability 0.550Same mean, much greater dispersion
C60.61 with probability 0.99; −1000 with probability 0.01approximately 50Same mean, rare catastrophe

This does not mean that standard RL must ignore every danger. A sufficiently negative catastrophe reward can lower expected return. The deeper problem is that safety, legality, irreversibility, and human harm are often poorly represented by a single compensatory scalar. Some outcomes should not become acceptable merely because frequent benefits offset them numerically.

A mean–variance objective, 𝔼[G]−λVar(G), rewards performance and penalizes instability. A chance-constrained formulation maximizes expected return while requiring P(failure)≤ε. CVaR focuses attention on the average severity of the worst tail. For losses rather than returns, the convention reverses: one usually minimizes upper-tail CVaR.

12. A governance ordering for critical systems

A defensible decision rule need not ask one metric to do every job:

  1. Declare non-compensatory invariants: safety, integrity, legal, audit, or human-rights constraints that average utility cannot buy away.
  2. Bound violation probability: use explicit chance constraints or reachability requirements.
  3. Characterize the tail: report quantiles, CVaR, worst credible scenarios, and recovery behavior.
  4. Optimize expected utility: among policies that remain admissible, select the strongest mean performance.
  5. Expose epistemic uncertainty: attach confidence bounds, model assumptions, data coverage, and residual unknowns.
  6. Keep judgment accountable: record who accepted the residual risk, on what evidence, for which operational context, and with what monitoring and rollback conditions.
invariants \;\rightarrow\; tail\ risk \;\rightarrow\; expected\ performance \;\rightarrow\; accountable\ decision

This matters in Test Authority work. Mean latency can pass while p99 violates an SLA; average detection can look strong while one critical failure class remains invisible; aggregate biometric performance can hide subgroup or tail harm; average availability can conceal an unacceptable probability of unrecoverable corruption.

13. Rare events require evidence beyond ordinary sampling

Observing no catastrophe in 10,000 trials does not demonstrate a probability below 10−6. Tail claims require evidence designed for the tail:

  • targeted simulation and importance sampling;
  • stress testing and Adaptive Stress Testing;
  • fault injection, mutation, and controlled interface or observability perturbations;
  • adversarial scenario generation;
  • causal analysis and domain expertise;
  • confidence bounds, sensitivity analysis, and conservative margins;
  • post-deployment monitoring with explicit stop or rollback rules.

Evidence can constrain judgment; it cannot remove the normative decision about what counts as unacceptable.

14. Bridge to MMALS and evidence-guided governance

The RL vocabulary provides a useful—but currently hypothetical—bridge for MMALS:

RL/MDP objectCandidate MMALS interpretation
StateA belief state over evidence, regime, context, system health, and unresolved contradiction
ActionReplicate, collect targeted evidence, explore, falsify, exploit, abstain, or escalate
Reward / costInformation gain, decision utility, latency, compute, human effort, safety risk, and evidence debt
TransitionHow actions change the evidence state and system knowledge
PolicyA governed rule for choosing the next evidence-producing action

Because the true situation may be only partially observed, the eventual formalism may be closer to a belief-state MDP or POMDP than to the fully observed six-state rover. This is a research direction. It has not yet been validated as an operational MMALS or Test Authority controller.
